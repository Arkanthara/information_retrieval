Résumé exécutif

Question 1 · Sparse Embedding

Modèle Vectoriel (VSM)

Les documents sont encodés en vecteurs TF-IDF dans $\mathbb{R}^M$. La similarité entre document et requête est calculée par le cosinus des vecteurs. Le RSV est continu dans $[0,1]$.

Question 2 · Probabilistic IR

Modèle Probabiliste (BIR)

On estime la probabilité de pertinence $P(R|d_j,q)$ via le rapport de cotes bayésien. Sous l'hypothèse d'indépendance binaire, le RSV = log-odds ratio, conduisant à BM25.

Concept central

RSV — Retrieval Status Value

Fonction $\text{RSV}(d_j, q) \in \mathbb{R}$ mesurant la pertinence du document $d_j$ par rapport à la requête $q$. L'ordonnancement par RSV décroissant produit la liste de résultats.

Point commun fondamental

TF-IDF : embedding de base

Les deux modèles partent du même embedding $w_{ij} = \text{tf}_{ij} \cdot \text{idf}_i$. Le VSM l'utilise géométriquement ; le BIR l'utilise probabilistement. L'IDF réapparaît naturellement dans les deux.

Réponse modèle d'oral

Question 1 — Modèle Vectoriel

Le modèle vectoriel commence par transformer chaque document textuel en un vecteur numérique dans un espace de dimension $M$, où $M$ est la taille du vocabulaire. Cette transformation se fait via l'embedding TF-IDF.

Pour chaque terme $i$ dans le document $j$, on calcule un poids $w_{ij} = \text{tf}_{ij} \cdot \text{idf}_i$. La fréquence des termes (TF) capture l'importance locale du terme dans ce document, tandis que la fréquence inverse de document (IDF) mesure son pouvoir discriminant dans la collection : un terme présent dans tous les documents a un IDF proche de zéro, donc un poids nul.

Chaque document $d_j$ devient ainsi un vecteur colonne de la matrice terme-document $W \in \mathbb{R}^{M \times N}$. La requête, traitée selon le paradigme Query-by-Example, est projetée dans ce même espace.

La pertinence est alors calculée comme la similarité cosinus entre le vecteur document et le vecteur requête — c'est-à-dire le cosinus de l'angle entre ces deux vecteurs. Cette mesure est invariante à la longueur des documents et dérive directement de la notion d'intersection ensembliste étendue aux embeddings continus. Les documents sont finalement ordonnés par RSV décroissant.

Question 2 — Modèle Probabiliste (BIR)

Le modèle probabiliste repose sur le Probability Ranking Principle de Robertson (1977) : le système optimal classe les documents par ordre décroissant de probabilité de pertinence $P(R = \text{vrai} \mid d_j, q)$.

Pour éviter de normaliser cette probabilité, on utilise le rapport de cotes bayésien : $O(R \mid d_j, q) = P(R \mid d_j, q) / P(\bar{R} \mid d_j, q)$. Via le théorème de Bayes, ce ratio est proportionnel au rapport de vraisemblances $P(d_j \mid R, q) / P(d_j \mid \bar{R}, q)$.

L'hypothèse Binary Independence — occurrences binaires et indépendantes des termes — permet de factoriser cette vraisemblance. Après passage au logarithme et simplification, le RSV devient une somme de log-odds pondérée par les indicateurs de présence des termes communs entre le document et la requête.

À l'initialisation sans feedback, ce modèle retrouve l'IDF classique. Avec du pseudo-feedback, les estimations de probabilité se raffinent itérativement. Cette approche a été formalisée par Robertson et Sparck Jones, conduisant au modèle BM25 qui intègre la fréquence des termes et la longueur du document — encore utilisé aujourd'hui dans Elasticsearch et Lucene.

Question 1 · Modèle Vectoriel (VSM)

Pipeline global
Documents bruts → Vocabulaire → Embedding TF-IDF → Espace vectoriel $\mathbb{R}^M$ → Query-by-Example → Cosine Similarity → Liste ordonnée

Étape 0 — Pourquoi pas le Modèle Booléen ?

Le modèle booléen est le point de départ historique. Chaque terme $t_i$ est représenté par un vecteur 1-hot (one-hot encoding) de dimension $M$ :

One-Hot encoding (Binary embedding)
$$t_i = [\delta_{ik}]_{k=1}^M \in \{0,1\}^M \qquad \text{avec } \delta_{ik} = \begin{cases}1 & \text{si } k=i \\ 0 & \text{sinon}\end{cases}$$

Le document est la disjonction logique des termes contenus : $d_j = \bigvee_{i \in \mathcal{I}_j} t_i$. Tous les documents se situent aux sommets de l'hypercube $\{0,1\}^M$. La requête est une expression logique (AND/OR/NOT) convertie en forme normale disjonctive (DNF).

Problème fondamental
Le RSV booléen est binaire : $\text{RSV}(d_j,q) \in \{0,1\}$. Il n'y a aucun ordonnancement parmi les documents pertinents, aucune gradation. Deux besoins émergent : (1) un formalisme de requête flexible → Query-by-Example, (2) un continuum de pertinence → $\text{RSV} \in [0,1]$.

Étape 1 — Bag of Words & TF-IDF Embedding

Term Frequency (TF)

Plutôt que de noter simplement la présence/absence d'un terme, on compte ses occurrences. L'hypothèse fondatrice du modèle Bag of Words : plus un mot apparaît dans un document, plus il le représente.

Définition — Fréquence normalisée
$$\text{tf}_{ij} \;\stackrel{\text{def}}{=}\; \frac{f_{ij}}{\max_k f_{kj}} \qquad \Rightarrow \quad \max_i \text{tf}_{ij} = 1$$

où $f_{ij}$ est le nombre brut d'occurrences du terme $i$ dans le document $j$. La normalisation par le terme le plus fréquent permet de comparer des documents de longueurs différentes.

Limite du BoW
L'ordre des mots et la structure (titre, paragraphes) sont perdus. Seules les fréquences sont conservées. Cependant, c'est une simplification utile qui fonctionne bien en pratique.

Inverse Document Frequency (IDF)

La TF seule n'est pas suffisante : un terme très fréquent dans tous les documents (ex. « the », « est ») n'est pas discriminant. L'IDF mesure le pouvoir discriminant du terme $i$ dans la collection :

Définition — Inverse Document Frequency
$$\text{idf}_i \;\stackrel{\text{def}}{=}\; \log\frac{N}{n_i}$$

où $n_i$ est le nombre de documents contenant le terme $i$.

Cas$n_i$$\text{idf}_i$Interprétation
Terme dans tous les docs$n_i \approx N$$\approx 0$Non discriminant (stopword)
Terme rare$n_i \ll N$GrandTrès discriminant, spécifique
Terme présent dans 1 doc$n_i = 1$$\log N$Maximum de discriminance

Poids TF·IDF et matrice terme-document

Le poids du terme $i$ dans le document $j$ combine les deux facteurs :

Schéma de pondération TF·IDF
$$w_{ij} = \text{tf}_{ij} \cdot \text{idf}_i$$ $$W = \begin{pmatrix} w_{11} & \cdots & w_{1N} \\ \vdots & w_{ij} & \vdots \\ w_{M1} & \cdots & w_{MN} \end{pmatrix} \in \mathbb{R}^{M \times N}$$

Les colonnes de $W$ encodent les documents, les lignes encodent les termes :

  • Embedding document : $d_j = W_{\cdot j} = [w_{1j}, \ldots, w_{Mj}]^T \in \mathbb{R}^M$
  • Embedding terme : $t_i = (W_{i\cdot})^T = [w_{i1}, \ldots, w_{iN}]^T \in \mathbb{R}^N$ (utilisé en LSI)

Étape 2 — Géométrie de l'embedding TF-IDF

Il est instructif d'observer la structure algébrique de l'embedding. En développant $d_j$ :

Interprétation géométrique
$$d_j = \sum_i w_{ij} e_i = \sum_i (\text{tf}_{ij} \cdot \text{idf}_i) e_i = \sum_i \text{tf}_{ij} \underbrace{\text{idf}_i \cdot e_i}_{\tau_i}$$

où $\{e_i\}$ est la base canonique de $\mathbb{R}^M$ et $\tau_i = \text{idf}_i \cdot e_i$ est la base discriminante.

  • $\text{idf}_i$ (commun à tous les documents) : échelle la dimension $i$ proportionnellement au pouvoir discriminant du terme → étire les axes importants.
  • $\text{tf}_{ij}$ : coordonnée réelle du document $j$ dans cette base discriminante.
Intuition géométrique clé
L'IDF déforme l'espace vectoriel : les axes correspondant aux termes discriminants sont étirés, ceux des termes communs sont contractés. Un document proche d'une requête dans cet espace partage des termes importants et discriminants.

Étape 3 — Mesures de similarité : de l'intersection ensembliste au continu

L'idée de base : la similarité entre un document et une requête devrait refléter leur intersection ensembliste. En notation binaire : $\text{RSV}(\hat{d}_j, \hat{q}) = |\hat{d}_j \cap \hat{q}|$. En version algébrique : $\langle d_j, q \rangle = \sum_i w_{ij} w_{iq}$. Plusieurs extensions continues existent :

MesureFormule Continue (TF-IDF)Formule BinairePropriété
Matching $\langle d_j, q \rangle = \sum_i w_{ij}w_{iq}$ $|\hat{d}_j \cap \hat{q}|$ Sensible à la longueur
Cosinus ★ $\dfrac{\langle d_j, q \rangle}{\|d_j\|\|q\|}$ $\dfrac{|\hat{d}_j \cap \hat{q}|}{|\hat{d}_j|^{1/2}|\hat{q}|^{1/2}}$ Invariant à la norme
Dice $\dfrac{2\langle d_j, q \rangle}{\sum_i(w_{ij}+w_{iq})}$ $\dfrac{2|\hat{d}_j \cap \hat{q}|}{|\hat{d}_j|+|\hat{q}|}$ Moyenne harmonique de precision/recall
Overlap $\dfrac{\langle d_j, q \rangle}{\min(\sum_i w_{ij},\sum_i w_{iq})}$ $\dfrac{|\hat{d}_j \cap \hat{q}|}{\min(|\hat{d}_j|,|\hat{q}|)}$ Favorise la spécificité
Jaccard $\approx \dfrac{\langle d_j, q \rangle}{\sum_i \max(w_{ij},w_{iq})}$ $\dfrac{|\hat{d}_j \cap \hat{q}|}{|\hat{d}_j \cup \hat{q}|}$ Intersection / Union

Étape 4 — Cosine Similarity comme RSV

La mesure la plus utilisée en pratique est la similarité cosinus, extension naturelle de l'intersection ensembliste aux embeddings continus :

Cosine Similarity — Retrieval Status Value
$$\text{RSV}(d_j, q) \;\stackrel{\text{def}}{=}\; \cos\!\left(\angle(d_j, q)\right) = \frac{\langle d_j, q \rangle}{\|d_j\|\|q\|} = \frac{d_j^T q}{\|d_j\|\|q\|} = \frac{\sum_i w_{ij}w_{iq}}{\left(\sum_i w_{ij}^2\right)^{1/2}\left(\sum_i w_{iq}^2\right)^{1/2}}$$

Propriétés clés de la similarité cosinus

  • Invariance à la norme : mesure l'angle, pas la longueur. Un document deux fois plus long avec les mêmes termes a un cosinus = 1 avec lui-même.
  • RSV = 0 si aucun terme en commun (vecteurs orthogonaux).
  • RSV = 1 si les vecteurs sont parfaitement alignés (même profil de termes).
  • Avec des poids TF-IDF $\geq 0$, on a toujours $\text{RSV} \in [0,1]$.

Étape finale : ranking

On calcule $\text{RSV}(d_j, q)$ pour tous les $N$ documents, puis on les trie par ordre décroissant. Le résultat est une liste ordonnée $d_{\pi(1)}, d_{\pi(2)}, \ldots$ telle que $\text{RSV}(d_{\pi(1)}, q) \geq \text{RSV}(d_{\pi(2)}, q) \geq \ldots$

Question 2 · Modèle Probabiliste (BIR / BM25)

Pipeline global
Documents bruts → Features binaires → Probability Ranking Principle → Bayesian Odds Ratio → Binary Independence → Log-Odds RSV → Estimation (IDF puis pseudo-feedback) → RSJ → BM25 → Liste ordonnée

Étape 1 — Probability Ranking Principle (Robertson, 1977)

Énoncé du PRP
Si un système classe les documents dans l'ordre décroissant de probabilité d'utilité pour l'utilisateur, alors l'efficacité globale du système sera la meilleure possible sur la base des données disponibles. — Stephen E. Robertson, Journal of Documentation, 1977

Formalisation : Pour une requête $q$, il existe un ensemble idéal $\mathcal{R}$ de documents pertinents. $R$ est une variable aléatoire de Bernoulli indiquant la pertinence. La tâche est d'estimer :

Objectif probabiliste
$$\text{Ranger les documents } d_j \text{ par ordre décroissant de } P(R = \text{vrai} \mid d_j, q)$$

L'ensemble $\mathcal{R}$ est estimé de manière itérative : le système fournit une réponse initiale, l'utilisateur juge des documents comme pertinents/non-pertinents, ces jugements sont utilisés comme feedback, et le processus se répète jusqu'à satisfaction.

Étape 2 — Décision Bayésienne & Rapport de Cotes

Plutôt que de définir un seuil absolu $P(R \mid d_j, q) > \tau$, on utilise le rapport de cotes bayésien (Odds Ratio) qui contourne le problème de normalisation :

Odds Ratio
$$O(R \mid d_j, q) = \frac{P(R \mid d_j, q)}{P(\bar{R} \mid d_j, q)}$$

On applique le théorème de Bayes :

Développement bayésien
$$O(R \mid d_j, q) = \frac{P(d_j \mid R, q) \cdot P(R \mid q)}{P(d_j \mid \bar{R}, q) \cdot P(\bar{R} \mid q)}$$

Comme $P(R \mid q)$ (et $P(\bar{R} \mid q)$) est constant pour tous les documents, l'ordonnancement est déterminé uniquement par :

Rapport de vraisemblances (suffisant pour le ranking)
$$O(R \mid d_j, q) \;\propto\; \frac{P(d_j \mid R, q)}{P(d_j \mid \bar{R}, q)}$$
Connexion avec la régression logistique
Si on suppose que $\log O(R \mid d_j, q)$ est une fonction log-linéaire des features du document : $\log O = \phi_\theta(d_j, q) = w^T d_j + w_0$, alors $P(R \mid d_j, q) = \sigma(w^T d_j + w_0)$ (fonction sigmoïde). Les paramètres $\theta$ peuvent être appris par régression logistique avec les jugements de pertinence comme exemples.

Étape 3 — Hypothèse Binary Independence

Pour rendre le calcul tractable, le modèle BIR pose deux hypothèses qui lui donnent son nom :

Hypothèse 1 · Binary

Occurrences binaires

L'occurrence de chaque terme $t_i$ dans le document est binaire : $w_{ij} \in \{0,1\}$ — présent ou absent. (On ignore les fréquences d'occurrence.)

Hypothèse 2 · Independence

Indépendance des termes

Les occurrences des termes sont conditionnellement indépendantes dans le document. C'est la même hypothèse naïve que dans le classifieur Naïve Bayes.

Sous ces deux hypothèses, la vraisemblance se factorise :

Factorisation sous l'hypothèse d'indépendance
$$P(d_j \mid R, q) = \prod_{i \in \mathcal{I}_j} P(t_i \mid R, q) \cdot \prod_{i \notin \mathcal{I}_j} \big(1 - P(t_i \mid R, q)\big)$$

Le premier produit porte sur les termes présents dans le document, le second sur les termes absents. On obtient donc le rapport de cotes :

Odds ratio factorisé
$$O(R \mid d_j, q) \propto \prod_{i \in \mathcal{I}_j} \frac{P(t_i \mid R, q)}{P(t_i \mid \bar{R}, q)} \cdot \prod_{i \notin \mathcal{I}_j} \frac{1-P(t_i \mid R, q)}{1-P(t_i \mid \bar{R}, q)}$$

Étape 4 — Dérivation du RSV BIR

On passe au logarithme (monotone, donc l'ordonnancement est préservé) :

Log-odds ratio (étape intermédiaire)
$$\log O(R \mid d_j, q) \propto \sum_{i \in \mathcal{I}_j} \left[ \log \frac{P(t_i \mid R, q)}{1-P(t_i \mid R, q)} + \log \frac{1-P(t_i \mid \bar{R}, q)}{P(t_i \mid \bar{R}, q)} \right]$$

Simplification clé : pour les termes absents de la requête ($i \notin \mathcal{I}_q$), on a $P(t_i \mid R, q) = P(t_i \mid \bar{R}, q)$, donc leur contribution est nulle. On peut donc restreindre la somme aux termes présents dans les deux :

RSV BIR — Formule finale
$$\text{RSV}(d_j, q) = \log O(R \mid d_j, q) \propto \sum_{i=1}^M w_{ij} \cdot w_{iq} \cdot c_i$$ $$\text{où}\quad c_i = \log \frac{P(t_i \mid R, q)}{1-P(t_i \mid R, q)} + \log \frac{1-P(t_i \mid \bar{R}, q)}{P(t_i \mid \bar{R}, q)}$$

avec $w_{ij}$ et $w_{iq}$ indicateurs binaires de présence du terme $i$ dans le document $j$ et la requête $q$. Le coefficient $c_i$ est le poids de pertinence du terme $i$.

Structure du RSV BIR
Le RSV est une somme de contributions par terme, où chaque terme contribue seulement s'il est présent à la fois dans le document ET dans la requête. Le coefficient $c_i$ encode à quel point la présence du terme $i$ est informative sur la pertinence du document.

Étape 5 — Estimation des probabilités : connexion avec l'IDF

Les probabilités $P(t_i \mid R, q)$ et $P(t_i \mid \bar{R}, q)$ doivent être estimées. On utilise un ensemble de pseudo-feedback $S$ (les $r$ premiers documents récupérés) :

  • $r_i$ : nombre de ces documents contenant le terme $i$
  • $n_i$ : nombre total de documents de la collection contenant le terme $i$

Initialisation (sans feedback — temps de requête)

Estimations initiales (agnostiques)
$$P(t_i \mid R, q) = \rho \text{ (constante)} \qquad P(t_i \mid \bar{R}, q) = \frac{n_i}{N}$$
Connexion fondamentale avec l'IDF
À l'initialisation, le second terme du coefficient $c_i$ devient : $$\log \frac{1-P(t_i \mid \bar{R}, q)}{P(t_i \mid \bar{R}, q)} = \log \frac{N-n_i}{n_i} \approx \log \frac{N}{n_i} = \text{idf}_i$$ L'IDF émerge naturellement du modèle probabiliste à l'initialisation. Ce n'est pas une heuristique, c'est une conséquence du raisonnement bayésien sans feedback.

Après retrieval (avec pseudo-feedback itératif)

Estimations avec feedback (r documents pertinents)
$$P(t_i \mid R, q) = \frac{r_i}{r} \qquad P(t_i \mid \bar{R}, q) = \frac{n_i - r_i}{N - r}$$

Le processus s'itère jusqu'à convergence : les nouvelles estimations modifient le RSV, ce qui change le top-$r$, ce qui modifie les estimations, etc.

Étape 6 — Modèle RSJ et formule BM25 (OKAPI)

Le modèle BIR de base a évolué vers le modèle Robertson-Sparck-Jones (RSJ) avec une pondération robuste, puis vers BM25 qui intègre la fréquence des termes et la longueur du document.

Poids RSJ

Robertson-Sparck-Jones Weight
$$w_i^{\text{RSJ}} = \log \frac{(r_i + 0.5)(N - R - n_i + r_i + 0.5)}{(n_i - r_i + 0.5)(R - r_i + 0.5)}$$

Le facteur $+0.5$ (add-half smoothing) évite les divisions par zéro et stabilise l'estimation.

BM25 — Best Match 25 (OKAPI)

BM25 étend RSJ en incorporant :

  • La fréquence tf du terme dans le document (saturation logarithmique)
  • La longueur du document normalisée par la longueur moyenne
Poids BM25 par terme
$$w_i^{\text{BM25}}(\text{tf}) = \frac{\text{tf}}{k_1\!\left((1-b) + b\,\dfrac{dl}{avdl}\right) + \text{tf}} \cdot w_i^{\text{RSJ}}$$
Score BM25 complet (formule de Robertson et al., 1995)
$$\text{RSV}^{\text{BM25}}(d_j, q) = \sum_{T \in Q} w^{(1)} \cdot \frac{(k_1+1)\,\text{tf}}{K + \text{tf}} \cdot \frac{(k_3+1)\,qtf}{k_3+qtf}$$ $$\text{où}\quad K = k_1\!\left((1-b) + b\,\frac{dl}{avdl}\right)$$
ParamètreSignificationValeur typiqueEffet
k₁Saturation de la TF1.2$k_1 \to \infty$ : TF linéaire ; $k_1 = 0$ : binaire
bNormalisation longueur0.75$b=0$ : pas de norm. ; $b=1$ : norm. complète
k₃Saturation de la TF requête7 ou 1000$k_3 \to \infty$ : ignore qtf
dlLongueur du document—Pénalise les longs documents
avdlLongueur moyenne docs—Référence pour la normalisation
BM25 : modèle de référence
BM25 est le modèle de référence en IR probabiliste. Il est implémenté dans Elasticsearch, Lucene, Solr, Whoosh et sert de baseline forte pour les systèmes modernes. En 2025, BM25+ est encore compétitif et sert souvent de première étape dans les pipelines de retrieval hybride.

Formules importantes

TF — Term Frequency BoW / VSM / BIR
$$\text{tf}_{ij} = \frac{f_{ij}}{\max_k f_{kj}}$$
Variables

$f_{ij}$ = occurrences brutes du terme $i$ dans doc $j$ ; max normalise

Propriété

$\max_i \text{tf}_{ij} = 1$ toujours. Normalise par rapport à la longueur.

Intuition

Plus un terme est fréquent dans un document, plus il le représente.

Exemple

Doc : « chat chat chien » → $f_{\text{chat}} = 2$, $f_{\text{chien}} = 1$, $\text{tf}_{\text{chat}} = 1$, $\text{tf}_{\text{chien}} = 0.5$

IDF — Inverse Document Frequency BoW / VSM / BIR
$$\text{idf}_i = \log \frac{N}{n_i}$$
Variables

$N$ = nb de docs ; $n_i$ = nb de docs contenant le terme $i$

Propriété

$\text{idf}_i \approx 0$ si terme omniprésent ; $\text{idf}_i = \log N$ si terme unique

Intuition

Mesure le pouvoir discriminant du terme. Pénalise les termes communs, valorise les termes rares.

Connexion BIR

Émerge naturellement de $\log\frac{1-n_i/N}{n_i/N} \approx \log(N/n_i)$ à l'initialisation probabiliste.

TF·IDF Weight & Document Vector Core Embedding
$$w_{ij} = \text{tf}_{ij} \cdot \text{idf}_i \qquad d_j = [w_{1j},\ldots,w_{Mj}]^T \in \mathbb{R}^M$$
Matrice W

$W \in \mathbb{R}^{M\times N}$ : lignes = termes, colonnes = documents

Géométrie

$d_j = \sum_i \text{tf}_{ij} \cdot \tau_i$ où $\tau_i = \text{idf}_i \cdot e_i$ est la base discriminante

Interprétation

Chaque axe de $\mathbb{R}^M$ correspond à un terme, pondéré par son importance globale (IDF)

Sparsité

La plupart des $w_{ij} = 0$ (sparse embedding). Le coût stockage est proportionnel au nombre de termes par document.

Cosine Similarity — RSV Vectoriel VSM
$$\text{RSV}(d_j, q) = \cos(\angle(d_j,q)) = \frac{\langle d_j, q \rangle}{\|d_j\|\|q\|} = \frac{\sum_i w_{ij}w_{iq}}{\left(\sum_i w_{ij}^2\right)^{1/2}\!\left(\sum_i w_{iq}^2\right)^{1/2}}$$
Plage

$\text{RSV} \in [0,1]$ avec TF-IDF positifs. $\text{RSV}=1$ si même direction, $0$ si orthogonaux.

Invariance

Invariant à la norme : indépendant de la longueur des documents. Un doc 2× plus long mais identique → cosinus = 1.

Dérivation

Extension algébrique de l'intersection ensembliste $|\hat{d}_j \cap \hat{q}|$ normalisée par $|\hat{d}_j|^{1/2}|\hat{q}|^{1/2}$.

Limite

Toujours 0 si aucun terme en commun (gap lexical). Problème de synonymie et polysémie → LSI.

Bayesian Odds Ratio — RSV Probabiliste BIR
$$O(R \mid d_j,q) = \frac{P(R|d_j,q)}{P(\bar{R}|d_j,q)} \propto \frac{P(d_j|R,q)}{P(d_j|\bar{R},q)} \quad\Rightarrow\quad \text{RSV} = \log O(R|d_j,q)$$
Avantage

Évite de fixer un seuil $\tau$ sur $P(R|d_j,q)$. Le rapport est monotone avec la probabilité.

Bayes

$P(R|q)$ constant → s'annule dans le ratio → il suffit d'estimer les vraisemblances $P(d_j|R,q)$.

RSV final

$\sum_i w_{ij}w_{iq}\left[\log\frac{P(t_i|R,q)}{1-P(t_i|R,q)} + \log\frac{1-P(t_i|\bar{R},q)}{P(t_i|\bar{R},q)}\right]$

Lien IDF

À l'init : $\log\frac{1-n_i/N}{n_i/N} \approx \text{idf}_i$. Le BIR sans feedback ≈ TF·IDF !

BM25 — Best Match 25 (OKAPI) RSJ → BM25
$$\text{RSV}^{\text{BM25}} = \sum_{T \in Q} w^{(1)}_{\text{RSJ}} \cdot \underbrace{\frac{(k_1+1)\,\text{tf}}{k_1\!\left((1-b)+b\frac{dl}{avdl}\right)+\text{tf}}}_{\text{saturation TF + norm. longueur}} \cdot \underbrace{\frac{(k_3+1)\,qtf}{k_3+qtf}}_{\text{term freq. requête}}$$
Saturation TF

Le facteur TF est borné : il tend vers $\frac{k_1+1}{k_1} \approx 1.83$ quand $tf \to \infty$. Évite que les termes très fréquents dominent.

Norm. longueur

$b=0.75$ pénalise les longs documents (supposés diluer les termes pertinents).

Extension

BM25+ corrige un problème de BM25 : les documents où un terme est absent reçoivent un score positif avec BM25. BM25+ y remédie.

Usage

Implémenté dans Elasticsearch, Lucene, Solr. Baseline forte pour les benchmarks TREC. Encore compétitif en 2025.

Perspective historique

1950s–1960s
Modèle Booléen & Index inversé
Premiers systèmes de recherche d'information. Maron (1960) introduit déjà l'idée de ranking probabiliste. Requêtes booléennes pures : opérateurs AND/OR/NOT.
1972–1975
Vector Space Model (Salton & al.)
G. Salton et M.J. McGill introduisent le VSM dans le cadre du projet SMART. TF-IDF devient le schéma de pondération standard. La similarité cosinus est formalisée.
1977
Probability Ranking Principle (Robertson)
Stephen Robertson énonce le PRP dans le Journal of Documentation. Ce principe fonde toute l'IR probabiliste moderne. Le modèle BIR est formalisé par Robertson et Sparck Jones.
1988–1994
Latent Semantic Indexing (LSI)
Deerwester et al. (1990) publient LSI. La SVD est appliquée à la matrice TF-IDF pour dériver des concepts latents. Première approche de réduction dimensionnelle pour l'IR.
1994–1995
BM25 / OKAPI (Robertson, Walker, et al.)
BM25 est présenté à TREC-3 par Robertson et al. (Okapi at TREC-3, 1995). Le modèle RSJ avec saturation TF et normalisation de longueur devient le standard. BM25 domine les benchmarks TREC pendant 15+ ans.
2013
Word2Vec (Mikolov et al.)
Embeddings denses neuraux. Les représentations distribuées capturent la sémantique que TF-IDF ne peut pas saisir. Début de l'ère des dense embeddings.
2017–2020
Transformers & Dense Retrieval (BERT, DPR)
BERT (Devlin, 2018) révolutionne les embeddings. DPR (Karpukhin, 2020) applique les bi-encodeurs au retrieval. BM25 reste cependant une baseline forte et est utilisé dans les pipelines hybrides.
2024–2025
Hybrid Retrieval & RAG
Les systèmes modernes combinent BM25 (sparse) et embeddings denses (FAISS, pgvector). BM25 gère les correspondances exactes, les embeddings la sémantique. BM25+ et SPLADE remplacent progressivement BM25 classique.
08

Lien avec les systèmes modernes

Search Engines

BM25 dans Elasticsearch

Elasticsearch utilise BM25 par défaut depuis la version 5.0. Les paramètres $k_1$ et $b$ sont configurables par champ. TF-IDF était l'algorithme par défaut avant 2016.

Dense Retrieval

Embeddings denses vs sparse

Les embeddings TF-IDF/BM25 sont sparse ($M \approx 10^4$–$10^6$, beaucoup de zéros). Les embeddings BERT/S-BERT sont denses ($d \approx 768$, tous non-nuls). Sparse = meilleures correspondances exactes ; dense = meilleure sémantique.

Hybrid Retrieval

BM25 + Dense : RRF

Les pipelines modernes (RAG notamment) combinent BM25 et dense retrieval via le Reciprocal Rank Fusion. BM25 gère les termes exacts, les embeddings la paraphrase. La combinaison surpasse chaque approche isolée.

Learned Sparse Embeddings

SPLADE & co.

SPLADE (Formal et al., 2021) apprend des embeddings sparse en espace de vocabulaire (comme TF-IDF/BM25), mais via un transformer. Combine la sparsité utile pour les index inversés et la représentation sémantique des LLMs.

RAG — Retrieval-Augmented Generation

BM25 dans les pipelines RAG

Dans les architectures RAG (Lewis et al., 2020), la première étape de retrieval utilise souvent BM25 ou un hybride. Le re-ranking (cross-encodeur BERT) affine ensuite les résultats pour le LLM.

Re-ranking

BM25 + Cross-Encoder

Architecture en deux étapes : (1) BM25 récupère $k$ = 100–1000 candidats rapidement ; (2) un cross-encoder (BERT fine-tuné) re-classe les candidats avec toute la puissance du transformer. Efficiency + accuracy.

Pourquoi BM25 résiste aux LLMs
BM25 présente des avantages spécifiques qui le maintiennent pertinent : (1) correspondances exactes de termes techniques et entités nommées (identifiants, codes, noms propres) — les embeddings denses les traitent mal ; (2) efficacité via l'index inversé — $O(\text{postings})$ alors que les embeddings denses nécessitent une recherche ANN ; (3) interprétabilité — on peut expliquer pourquoi un document est pertinent. En 2025, le retrieval hybride sparse+dense est la norme dans les systèmes de production.

Questions d'examen possibles

Niveau facile
Qu'est-ce que le RSV (Retrieval Status Value) ? ▾

Le RSV est une fonction $\text{RSV}(d_j, q) \in \mathbb{R}$ qui mesure la pertinence du document $d_j$ par rapport à la requête $q$. L'ordonnancement des documents par RSV décroissant produit la liste de résultats répondant à la requête. Dans le modèle vectoriel, le RSV est la similarité cosinus. Dans le modèle probabiliste, c'est le log-rapport de cotes bayésien. La définition du RSV est le problème central de l'IR.

Quelle est la différence entre TF et IDF ? Que représente chacun ? ▾

TF (Term Frequency) : $\text{tf}_{ij} = f_{ij}/\max_k f_{kj}$ mesure l'importance locale d'un terme dans un document spécifique. Un terme fréquent dans un document est supposé le représenter. Varie de 0 à 1.

IDF (Inverse Document Frequency) : $\text{idf}_i = \log(N/n_i)$ mesure le pouvoir discriminant global d'un terme dans toute la collection. Un terme présent dans tous les documents a IDF ≈ 0 (non discriminant). Un terme rare a un IDF élevé.

Le produit $w_{ij} = \text{tf}_{ij} \cdot \text{idf}_i$ combine les deux : un terme fréquent dans ce document ET rare dans la collection aura un poids élevé. C'est ce que reflète un nuage de tags : la taille est proportionnelle au poids TF-IDF.

Pourquoi le modèle booléen n'est-il pas satisfaisant ? ▾

Le modèle booléen présente trois problèmes fondamentaux : (1) RSV binaire $\{0,1\}$ : aucun ordonnancement parmi les documents pertinents ou non-pertinents — tous les documents pertinents sont équivalents ; (2) Sensibilité à la formulation : une petite variation de la requête peut donner 0 ou des milliers de résultats ; (3) Requêtes difficiles à exprimer : l'utilisateur doit formellement coder sa recherche en logique booléenne (AND/OR/NOT), ce qui est peu naturel. La solution : le paradigme Query-by-Example avec un RSV continu dans $[0,1]$.

Niveau intermédiaire
Comment la similarité cosinus est-elle dérivée de la notion d'intersection ensembliste ? ▾

En notation ensembliste binaire, la similarité entre document et requête est $|\hat{d}_j \cap \hat{q}|$ — le nombre de termes en commun. En version algébrique binaire, cela correspond au produit scalaire $\langle d_j, q \rangle = \sum_i w_{ij}w_{iq}$ avec $w_{ij} \in \{0,1\}$. Ce produit scalaire est sensible à la longueur : un long document contenant tous les termes de la requête l'emporterait toujours. En normalisant par $\|d_j\|\|q\|$ (racines carrées des tailles), on obtient la similarité cosinus : $\cos(\angle(d_j,q)) = \frac{\langle d_j,q\rangle}{\|d_j\|\|q\|}$. L'extension au cas continu (TF-IDF) suit naturellement en remplaçant les indicateurs binaires par les poids réels $w_{ij}$.

Quelle est la structure du modèle probabiliste BIR ? Pourquoi « Binary Independence » ? ▾

Le modèle BIR repose sur deux hypothèses fondatrices qui lui donnent son nom : (1) Binary : l'occurrence de chaque terme dans le document est binaire — présent ($w_{ij}=1$) ou absent ($w_{ij}=0$). On ignore les fréquences. (2) Independence : les occurrences des termes sont conditionnellement indépendantes dans le document étant donné la pertinence. Ces hypothèses permettent de factoriser $P(d_j|R,q)$ en un produit sur les termes individuels. C'est la même hypothèse que dans Naïve Bayes. La dérivation part du rapport de cotes bayésien $O(R|d_j,q) \propto P(d_j|R,q)/P(d_j|\bar{R},q)$, qui, après factorisation et passage au log, donne un RSV = somme de log-odds par terme présent dans les deux.

Comment l'IDF émerge-t-elle naturellement du modèle probabiliste BIR ? ▾

À l'initialisation du BIR, sans aucun feedback de pertinence, les estimations sont : $P(t_i|R,q) = \rho$ (constante arbitraire) et $P(t_i|\bar{R},q) = n_i/N$ (fréquence dans la collection). Le second terme du coefficient $c_i$ devient alors : $\log\frac{1-P(t_i|\bar{R},q)}{P(t_i|\bar{R},q)} = \log\frac{1-n_i/N}{n_i/N} = \log\frac{N-n_i}{n_i} \approx \log\frac{N}{n_i} = \text{idf}_i$. Ainsi, l'IDF n'est pas une heuristique : c'est la conséquence naturelle du raisonnement bayésien probabiliste lorsqu'on n'a pas d'information sur la pertinence. Cela prouve une profonde cohérence entre les approches géométrique et probabiliste de l'IR.

Niveau difficile
Décrivez la dérivation complète du RSV BIR, en explicitant les étapes algébriques clés. ▾

Étape 1 — Ratio de vraisemblances : $O(R|d_j,q) \propto P(d_j|R,q)/P(d_j|\bar{R},q)$.

Étape 2 — Factorisation (Binary Independence) : $P(d_j|R,q) = \prod_{i \in \mathcal{I}_j} P(t_i|R,q) \prod_{i \notin \mathcal{I}_j}(1-P(t_i|R,q))$

Étape 3 — Ratio produit : $O(R|d_j,q) \propto \prod_{i \in \mathcal{I}_j} \frac{P(t_i|R,q)}{P(t_i|\bar{R},q)} \prod_{i \notin \mathcal{I}_j} \frac{1-P(t_i|R,q)}{1-P(t_i|\bar{R},q)}$

Étape 4 — Manipulation algébrique : On multiplie le second produit par $\prod_{i \in \mathcal{I}_j}[\cdot]^{-1}[\cdot]$ pour que les deux produits portent sur $i \in \mathcal{I}_j$. Le terme complémentaire (sur tous les $i$) est constant pour tous les documents. On obtient $\log O \propto \sum_{i \in \mathcal{I}_j} c_i$ avec $c_i = \log\frac{P(t_i|R,q)}{1-P(t_i|R,q)} + \log\frac{1-P(t_i|\bar{R},q)}{P(t_i|\bar{R},q)}$.

Étape 5 — Restriction à la requête : Pour $i \notin \mathcal{I}_q$, $c_i = 0$ (les proba sont égales). Donc la somme se restreint à $i \in \mathcal{I}_j \cap \mathcal{I}_q$, encodé par $w_{ij}w_{iq}$.

Comment BM25 corrige-t-il les lacunes du modèle BIR de base ? Quel est le rôle exact des paramètres k₁ et b ? ▾

BIR de base suppose des occurrences binaires et ignore la longueur du document. BM25 introduit deux corrections : (1) Saturation TF : le facteur $\frac{(k_1+1)tf}{K+tf}$ est une fonction croissante et saturante de $tf$. Quand $tf \to \infty$, il tend vers $\frac{k_1+1}{k_1}$ (fini). Cela évite que des termes très fréquents dominent le score. $k_1=0$ rend le modèle purement binaire comme BIR ; $k_1 \to \infty$ rend la TF linéaire. (2) Normalisation de longueur via $K = k_1((1-b)+b\cdot dl/avdl)$. $b=0$ : pas de normalisation (longueur ignorée). $b=1$ : normalisation complète par la longueur. $b=0.75$ est un compromis empirique : un long document est supposé contenir plus de termes « dilués » ; BM25 le pénalise proportionnellement. L'intuition est que si un document est deux fois plus long que la moyenne, les fréquences de ses termes doivent être divisées par un facteur intermédiaire.

Quel est le paradigme Query-by-Example (QbE) et pourquoi est-il essentiel dans le VSM ? ▾

Dans le VSM, les documents sont projetés dans $\mathbb{R}^M$ via TF-IDF. Pour que le RSV (cosinus) ait un sens, la requête doit être dans le même espace. Le paradigme QbE consiste à traiter la requête comme un « document exemple » et à la projeter dans $\mathbb{R}^M$ avec le même embedding. $q = [w_{1q}, \ldots, w_{Mq}]^T$ où $w_{iq} = \text{tf}_{iq} \cdot \text{idf}_i$ avec $\text{tf}_{iq}$ la fréquence du terme $i$ dans la requête. Ce paradigme est essentiel pour trois raisons : (1) uniformité de la représentation — documents et requêtes dans le même espace ; (2) flexibilité — la requête peut être n'importe quel document exemple, pas seulement un texte court ; (3) cohérence algébrique — le cosinus est bien défini entre deux vecteurs du même espace. En LSI, la requête est en plus projetée dans l'espace des concepts $\mathbb{R}^K$.

Pièges classiques

⚠
Confondre TF et IDF : TF est local au document (mesure la fréquence dans UN document). IDF est global à la collection (mesure la rareté dans TOUTE la collection). $\text{idf}_i$ ne dépend pas de $j$ — c'est le même pour tous les documents.
⚠
Croire que le cosinus mesure une distance : La similarité cosinus mesure un angle, pas une distance euclidienne. La distance $\|d_j - q\|$ est différente et sensible à la norme. L'examinateur peut demander pourquoi on n'utilise pas la distance euclidienne comme RSV.
⚠
Oublier l'hypothèse d'indépendance dans BIR : Le nom « Binary Independence » repose sur DEUX hypothèses. L'oublier est une erreur courante. Préciser que les termes sont supposés indépendants conditionnellement à $R$ — c'est la même hypothèse que Naïve Bayes.
⚠
Dire que l'IDF est une heuristique : L'IDF émerge naturellement du modèle probabiliste BIR à l'initialisation ($P(t_i|\bar{R},q) = n_i/N$). Ce n'est pas une heuristique ad hoc — c'est une conséquence du raisonnement bayésien. Ce point est souvent demandé à l'oral.
⚠
Confondre termes de la requête et indicateurs : Dans le RSV BIR, $w_{iq}$ est un indicateur binaire de présence du terme $i$ dans la requête (dans BIR de base). Dans BM25, $qtf$ est la fréquence du terme dans la requête. Ne pas confondre les deux.
⚠
Oublier que la matrice W est terme-document : $W \in \mathbb{R}^{M \times N}$ : lignes = termes ($M$), colonnes = documents ($N$). Le document $d_j$ est la colonne $j$ de $W$, le terme $t_i$ est la ligne $i$. Ne pas inverser.
⚠
Penser que BM25 = BIR avec des fréquences : BM25 intègre aussi la normalisation par la longueur du document via le paramètre $b$ et le ratio $dl/avdl$. Ce n'est pas juste « BIR + TF ». Sans la normalisation de longueur, les longs documents seraient systématiquement favorisés.
⚠
Croire que le VSM est interprétable uniquement géométriquement : Le VSM a aussi une interprétation algébrique (somme de produits $w_{ij}w_{iq}$) qui le relie à l'intersection ensembliste. La géométrie et l'algèbre sont deux vues du même modèle. L'examinateur peut demander les deux.

Fiche de révision finale

Pipeline VSM (Q1)

  • 1. Docs bruts → Vocabulaire $M$ termes
  • 2. $f_{ij}$ → $\text{tf}_{ij} = f_{ij}/\max_k f_{kj}$
  • 3. $n_i$ → $\text{idf}_i = \log(N/n_i)$
  • 4. $w_{ij} = \text{tf}_{ij} \cdot \text{idf}_i$ → Matrice $W \in \mathbb{R}^{M\times N}$
  • 5. $d_j = W_{\cdot j} \in \mathbb{R}^M$ (colonne)
  • 6. Requête $q \in \mathbb{R}^M$ (QbE, même embedding)
  • 7. $\text{RSV}(d_j,q) = \langle d_j,q\rangle/(\|d_j\|\|q\|)$
  • 8. Tri par RSV décroissant → ranked list

Pipeline BIR (Q2)

  • 1. Docs bruts → $w_{ij} \in \{0,1\}$ (indicateurs binaires)
  • 2. PRP : ranger par $P(R|d_j,q)$ décroissant
  • 3. Odds Ratio : $O(R|d_j,q) \propto P(d_j|R)/P(d_j|\bar{R})$
  • 4. Binary Indep. : factorisation en produit sur termes
  • 5. $\text{RSV} = \sum_i w_{ij}w_{iq} c_i$ (log-odds)
  • 6. Init. : $c_i \approx \text{idf}_i$ (sans feedback)
  • 7. Feedback : $P(t_i|R) = r_i/r$ → RSJ → BM25
  • 8. Tri par RSV décroissant → ranked list

Formules essentielles

  • TF : $\text{tf}_{ij} = f_{ij}/\max_k f_{kj}$
  • IDF : $\text{idf}_i = \log(N/n_i)$
  • TF-IDF : $w_{ij} = \text{tf}_{ij} \cdot \text{idf}_i$
  • Cosine : $\langle d_j,q\rangle / (\|d_j\|\|q\|)$
  • BIR RSV : $\sum_i w_{ij}w_{iq}[\log\text{-odds}]$
  • BM25 TF-factor : $(k_1+1)tf / (K+tf)$
  • BM25 K : $k_1((1-b)+b\cdot dl/avdl)$
  • RSJ : $\log\frac{(r_i+.5)(N-R-n_i+r_i+.5)}{(n_i-r_i+.5)(R-r_i+.5)}$

Points différenciants clés

  • VSM vs BIR : géométrie vs probabilités
  • IDF : émerge naturellement dans BIR init.
  • Cosinus : invariant à la norme, dérivé de ∩
  • BIR "Binary" : $w_{ij} \in \{0,1\}$ (pas TF)
  • BIR "Independence" : termes indépendants (Naïve Bayes)
  • BM25 vs BIR : +TF saturée, +normalisation longueur
  • QbE : requête = document exemple dans $\mathbb{R}^M$
  • PRP : fondement du classement probabiliste (1977)

Connexions conceptuelles

  • Boolean → BoW : binaire → fréquences
  • BoW → VSM : fréquences → géométrie $\mathbb{R}^M$
  • BoW → BIR : fréquences → probabilités
  • BIR init ≈ TF-IDF : même IDF !
  • BIR → RSJ → BM25 : +smoothing, +TF, +longueur
  • VSM → LSI : TF-IDF → SVD → concepts latents
  • LSI → Word2Vec → BERT : linéaire → non-linéaire
  • BM25 → Hybrid : sparse + dense retrieval

Rappels à connaître par cœur

  • PRP : Robertson, Journal of Doc., 1977
  • BM25 : Robertson et al., TREC-3, 1995
  • Params BM25 défaut : $k_1 \approx 1.2$, $b \approx 0.75$
  • Matrice W : $M \times N$ (termes × documents)
  • $d_j \in \mathbb{R}^M$ = colonne de W
  • $t_i \in \mathbb{R}^N$ = ligne de W (pour LSI)
  • Implémentation : Elasticsearch, Lucene, Solr

Message clé pour l'oral
Les deux modèles (VSM et BIR) sont des deux lectures du même problème fondamental : comment quantifier la pertinence d'un document par rapport à une requête à partir d'un embedding TF-IDF. Le VSM répond géométriquement (angle entre vecteurs), le BIR probabilistiquement (log-vraisemblance de pertinence). La convergence entre les deux — l'IDF émergeant naturellement dans BIR — est la signature de leur cohérence profonde.
